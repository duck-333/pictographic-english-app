# 内容访问权益扣减测试报告

测试日期：
2026-07-23

## 1. 测试背景

记录 `CONTENT_ACCESS` 权益消费逻辑上线后的实际验证结果。

当前规则：

用户主动获取完整单词详情内容时：

- 服务端校验用户权益
- 有完整内容时消耗 1 次权益
- 无完整内容时不消费
- 列表展示类请求不消费

## 2. 测试环境

测试账号：

`user_id: 4`

初始权益：

30 次查词额度

测试环境：

微信开发者工具模拟器

验证数据来源：

MySQL：

`entitlement_transactions`

交易类型：

`CONTENT_ACCESS`

## 3. 测试结果

### 测试 1：首页/学习列表进入详情

操作：

打开 `study` 页面，进入单词详情。

结果：

新增一条 `CONTENT_ACCESS` 记录。

扣减：

-1

结论：

通过。

### 测试 2：首页刷新

操作：

返回首页或刷新列表。

结果：

未新增 `CONTENT_ACCESS`。

结论：

列表加载不会消费权益。

### 测试 3：收藏列表进入详情

操作：

搜索单词 -> 收藏 -> 从收藏列表进入详情。

结果：

新增 `CONTENT_ACCESS`。

扣减：

-1

结论：

符合规则。

说明：

收藏只是入口，不代表永久拥有内容权限。

### 测试 4：最近学习进入详情

操作：

从最近学习列表进入单词详情。

结果：

新增 `CONTENT_ACCESS`。

扣减：

-1

结论：

符合规则。

### 测试 5：词根/关联词访问

操作：

详情页点击词根。

情况 A：

词根没有完整内容。

结果：

未扣次数。

结论：

合理。

情况 B：

词根存在完整内容。

结果：

新增 `CONTENT_ACCESS`。

扣减：

-1。

当前规则：

有完整内容的关联词/词根视为新的学习对象访问。

### 测试 6：额度耗尽

操作：

消耗完全部查词次数后继续访问详情。

结果：

提示：

“剩余查词次数不足”

无法继续查看完整内容。

结论：

通过。

## 4. 当前正式规则总结

### 消费入口

会消费：

- 单词详情页主动访问
- 收藏进入详情
- 最近学习进入详情
- 有完整内容的词根/关联词详情

不会消费：

- 搜索列表
- 首页推荐列表
- 最近学习列表加载
- 收藏列表加载
- 无完整内容词条访问

## 5. 已解决问题记录

此前问题：

列表预加载请求自动携带 `Authorization`，导致非详情访问也进入权益消费流程。

修复后：

只有详情页主动访问：

```js
fetchWordById(..., {
  accessContent: true
})
```

才进入 `CONTENT_ACCESS` 消费流程。
