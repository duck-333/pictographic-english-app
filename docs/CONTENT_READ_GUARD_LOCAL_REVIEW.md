## 实际规则（初值待校准）

参数统一位于 `server/content-read-guard.mjs` 的 `CONTENT_READ_POLICY`：

| 参数 | 初值 | 含义 |
| --- | --- | --- |
| windowMs | 21600000（6小时） | 滚动观察窗口 |
| maxDistinct | 360 | 窗口内允许首次读取的不同普通词条数 |
| cooldownMs | 21600000（6小时） | 超限时临时冷却长度 |

这是按不同词条的读取速度判断：6小时内尝试第361个新词，等价于在该窗口持续超过平均60个新词/小时。前360个可以集中学习；第361个不发正文、不扣查词次数，开始6小时冷却。会员同样适用。它不是会员每天固定查词额度。

初值刻意给集中学习留出空间，同时覆盖低于原短时30次/分钟、但持续遍历词库的读取。没有真实学习数据支持，不能宣称不会误伤。后续需依据实际学习分布校准。极慢读取和多账号采集仍可能绕过此规则。

正常复习：窗口内已读同词不增加新词数，不延长该词的首次读取时间；原短时限频仍逐次执行。
集中学习：未达360个不同新词时照常访问；第361个触发冷却，剩余次数仍保留。
持续自动读取：即使每3秒请求一次（每分钟20次，低于原短时限速），持续获取新词仍触发冷却。

冷却期间：可复习当前滚动窗口仍有记录的已读词；新词被429拦截，返回 `CONTENT_READ_COOLDOWN` 和 `Retry-After`。被拒绝不会延长冷却。
到期：自动恢复，无需重新登录、付费或人工解封。代码要求冷却至少覆盖观察窗口，保证到期时旧的触发记录已过期。
细节：已读记录超过6小时后，该词再次读取也视为窗口内的新词；因此冷却中很早读过、已经过期的词也可能需要等冷却结束。

当前推荐词：继续使用原来的免费正文路径，匿名/登录/无次数/冷却中均不受新增规则影响，不计统计、不扣次数，原匿名限频保留。
其他匿名预览、无权限、词不存在、未提供全文均不增加读取统计。

## 数据与事务

迁移012同时提供在 `database/migrations` 和 `server/migrations`，只在本地隔离MySQL验证。

- `content_read_words`：稳定账号ID、服务端实际词条ID、窗口首次全文读取毫秒时间。主键 `(user_id, word_id)`，索引覆盖账号时间查询和过期清理。
- `content_read_cooldowns`：稳定账号ID、冷却截止毫秒时间，账号主键和过期索引。
- 不保存正文、IP、会话或额外身份信息。没有新增Redis、依赖或风控后台。
- 账号来自服务端会话验证；词条ID来自词库实际查找结果，大小写/别名对应同一个实际ID只计一次。
- 全文路由在调用既有 `consumeQuota` 时启用保护。以现有 `user_entitlements` 账号行锁串行化；判断、记词、扣次同一事务提交。保护事务使用 READ COMMITTED，避免不同账号在不存在的幂等键上产生间隙锁竞争。
- 旧扣次幂等键不变；重放也检查读词规则。锁后读取已提交账本，防并发重试重复扣次。保护路径遇到意外唯一键冲突回滚报错，不经旧的重复键补偿分支放行正文。
- 权益不足不插入读词记录；数据库失败不返回正文；事务失败同时回滚读词记录和扣次。会员也必须完成数据库判断才能取得普通词全文。
- 每个有权全文请求在账号锁下清理本账号过期记录。过期条件是 `first_read_ms <= now-windowMs` 和 `until_ms <= now`，恰好到期即可恢复。
- 休眠账号清理入口：`node scripts/cleanup-content-reads.mjs`，要求显式提供全部 `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD`。每批最多1000条，每次最多100批；不做迁移，不碰其他表。批量清理函数已在隔离MySQL测试；此命令没有对生产执行，也未安装线上定时任务。后续部署安排应单独配置周期执行。若改观察窗口，应同步使用一致策略并安排历史数据处理，不能事后恢复已清掉的历史。
