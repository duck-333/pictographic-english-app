# 内容权限与商业规则设计方案

版本：v1.0  
日期：2026-07-29  
适用范围：微信小程序、Node server、管理后台、用户权益系统、视频播放链路。

本文档定义《象形英语》小程序第一阶段商业闭环中的内容访问规则、权益消费规则、会员规则和 API 权限边界。后续涉及内容权限、权益扣减、视频访问、买书会员、分享奖励的开发，应以本文档为准。

## 1. 核心原则

1. 用户必须登录后才能查看完整学习内容。
2. 注册用户获得 30 次完整学习次数。
3. 每进入一个单词完整详情，消耗 1 次完整学习次数。
4. 会员期间可无限查看完整内容，不消耗次数。
5. 买书用户当前通过后台人工添加 30 天全站会员，后续扩展兑换码。
6. 普通无权益用户只能查看基础免费内容。
7. 权限判断必须在 server 完成，前端隐藏只能作为体验层处理，不能作为权限控制。
8. 付费内容字段不得通过公开接口、搜索接口、基础详情接口返回。

## C. 次数消费规则

### C1. 消费单位

一次完整学习次数对应一次完整单词详情访问。

完整单词详情访问指用户主动请求并获得以下完整学习内容中的任意组合：

- 象形拆解
- 完整改义
- 完整意象
- 视频片段
- 完整讲解视频
- 深度学习内容

### C2. 会消耗次数的场景

以下行为应视为主动进入完整学习内容，若用户不是有效会员，应消耗 1 次：

1. 从搜索结果进入单词完整详情。
2. 从首页推荐进入单词完整详情。
3. 从收藏列表进入单词完整详情。
4. 从最近学习列表重新进入单词完整详情。
5. 从关联词、词根、扩展内容跳转到另一个单词的完整详情。

第一阶段暂不支持“已学过免扣”“复习模式免扣”“同一单词永久解锁”。因此，用户重复进入同一个单词完整详情，仍按一次新的完整学习访问处理。

### C3. 不消耗次数的场景

以下行为不得消耗次数：

1. 首页浏览。
2. 搜索单词。
3. 搜索结果列表展示。
4. 首页推荐列表展示。
5. 收藏列表展示。
6. 最近学习列表展示。
7. 基础免费详情展示。
8. 权益状态查询。
9. 登录、注册、用户资料刷新。

### C4. 扣减成功条件

一次次数消费必须同时满足：

1. 用户已登录且身份有效。
2. 用户不是有效会员。
3. 用户剩余完整学习次数大于 0。
4. 用户主动请求完整学习内容。
5. server 成功完成权益校验和扣减。
6. server 返回完整内容或可恢复的访问结果。

如果用户是有效会员，应允许访问完整内容，但不扣次数。

### C5. 幂等与失败处理

完整内容访问请求必须携带客户端生成的 `clientRequestId` 或等价幂等标识。

同一个 `clientRequestId` 的重试请求不得重复扣减。若出现网络超时、客户端中断或视频加载失败，应允许用户在同一访问上下文中重试，不应额外消耗次数。

如果 server 已扣减但客户端未收到完整内容，应通过幂等查询或重试机制恢复本次访问结果，避免用户感知为“扣了次数但没看到内容”。

## D. 会员规则

### D1. 会员定义

会员为全站会员。会员有效期内，用户可以无限查看所有已发布单词的完整学习内容。

会员权益包括：

- 象形拆解
- 完整改义
- 完整意象
- 视频片段
- 完整讲解视频
- 深度学习内容

### D2. 会员访问规则

1. 会员访问完整内容不消耗完整学习次数。
2. 会员访问完整内容仍应记录学习行为，便于最近学习、数据分析和风控。
3. 会员访问完整内容仍应通过 server 权限校验。
4. 会员状态不得只由前端本地缓存判断。

### D3. 会员过期规则

会员过期后，用户恢复普通用户状态：

1. 若仍有剩余完整学习次数，可继续按次访问完整内容。
2. 若无剩余完整学习次数，只能查看基础免费内容。
3. 过期用户不得继续访问象形拆解、意象、视频、深度学习内容。

### D4. 会员与次数并存规则

会员期间不消耗次数。用户已有的剩余次数保留，会员过期后继续可用，除非未来另行定义次数有效期。

## E. 买书会员规则

### E1. 第一阶段：后台人工添加

正版书用户当前通过后台人工添加会员权益。

默认规则：

- 权益类型：全站会员
- 默认有效期：30 天
- 生效方式：管理员在后台人工添加
- 消耗规则：会员期间无限访问完整内容，不消耗次数
- 到期规则：到期后恢复普通用户状态

后台操作应记录：

1. 用户标识。
2. 会员开始时间。
3. 会员到期时间。
4. 权益来源：买书用户。
5. 操作管理员。
6. 操作备注。
7. 操作时间。

### E2. 第二阶段：兑换码系统

后续可扩展兑换码系统：

1. 后台生成兑换码。
2. 每个兑换码对应 30 天全站会员。
3. 用户在小程序内输入兑换码。
4. server 校验兑换码有效性。
5. 兑换成功后开通会员。
6. 兑换码绑定兑换用户，不可重复使用。
7. 后台可查看兑换状态和兑换记录。

兑换码至少应包含以下状态：

- 未使用
- 已使用
- 已作废
- 已过期

### E3. 第三阶段：订单自动化

未来若接入电商订单或微信支付，应由支付成功或订单确认事件自动发放会员。订单自动化上线前，后台人工添加仍是唯一正式买书会员发放方式。

## F. 分享奖励规则

### F1. 第一阶段状态

分享奖励第一阶段暂不开发，不应作为正式可见入口影响用户预期。

### F2. 目标规则

未来分享奖励规则如下：

1. 新用户注册成功获得 30 次完整学习次数。
2. 老用户邀请新用户成功注册后，老用户获得 30 次完整学习次数。
3. 新用户通过分享链接进入并完成注册登录，才算邀请成功。
4. 老用户分享链接应包含可追踪邀请人标识。
5. 奖励发放必须写入权益流水。

### F3. 防刷原则

分享奖励上线前必须具备基础防刷规则：

1. 同一个新用户只能绑定一个邀请人。
2. 同一微信身份不得重复领取新用户注册奖励。
3. 老用户不能邀请自己。
4. 同一设备、手机号、openid 等高风险重复注册行为应进入风控或人工复核。
5. 后台应能查询分享奖励来源和被邀请用户。

## G. API 权限设计原则

### G1. 返回对象分层

API 应明确区分基础内容和完整内容。

`basicWord` 用于公开或半公开场景：

- 搜索结果
- 首页推荐
- 基础详情
- 收藏列表
- 最近学习列表
- 无权益锁定态页面

`basicWord` 可以包含：

- id
- word
- phonetic
- basicMeaning
- coverImage
- 基础词卡展示所需字段
- access 状态摘要

`basicWord` 不得包含：

- 象形拆解详细内容
- 完整改义
- 完整意象
- 视频 URL
- 视频 fileId
- 完整视频播放地址
- 深度学习内容

`fullWord` 仅用于完整权限通过后的场景：

- 已登录且有剩余次数
- 有效会员
- 后台管理员预览

`fullWord` 可以包含：

- basicWord 的全部字段
- 象形拆解
- 完整改义
- 完整意象
- 视频片段
- 完整讲解视频
- 深度学习内容
- 权益消费结果

### G2. 推荐接口原则

建议完整内容访问使用会产生明确副作用的接口，例如：

```text
POST /api/words/:id/access
```

该接口负责：

1. 校验登录态。
2. 判断会员状态。
3. 判断剩余次数。
4. 执行扣减或会员免扣。
5. 返回完整内容。
6. 返回本次访问结果。

搜索、首页、基础详情等接口不得触发扣减。

### G3. 权限结果字段

完整内容接口建议返回明确的访问状态：

```json
{
  "access": {
    "level": "full",
    "canAccessFull": true,
    "charged": true,
    "chargeAmount": 1,
    "remainingQuota": 29,
    "membershipActive": false,
    "reason": null
  }
}
```

无权限时应返回基础内容和锁定原因，而不是只返回通用错误：

```json
{
  "basicWord": {},
  "access": {
    "level": "basic",
    "canAccessFull": false,
    "charged": false,
    "remainingQuota": 0,
    "membershipActive": false,
    "reason": "QUOTA_INSUFFICIENT"
  }
}
```

### G4. 视频权限原则

视频属于付费内容。任何公开接口、搜索接口、基础详情接口不得返回视频播放地址。

视频字段只能在完整内容权限通过后返回。后续接入腾讯云 VOD 播放签名时，应优先返回短时有效播放凭证，而不是长期可复制 URL。

### G5. 前端职责

前端负责：

1. 根据 API 返回结果展示基础内容、完整内容或锁定态。
2. 在用户进入完整内容前提示登录或权益消耗。
3. 展示剩余次数、会员状态、到期时间。
4. 处理网络失败、视频失败、权益不足等体验状态。

前端不得作为唯一权限边界。

## H. 后续开发注意事项

1. 先完成 server 侧 `basicWord` / `fullWord` 权限分层，再优化前端展示。
2. 未登录用户请求完整内容时，server 不得返回付费字段。
3. 已登录但无次数、非会员用户请求完整内容时，应返回基础内容和锁定原因。
4. 会员用户访问完整内容时，应记录学习行为，但不得扣减次数。
5. 买书会员人工添加流程需要后台操作记录，便于追踪和售后。
6. 分享奖励第一阶段暂不开发，前端不应提前露出强承诺入口。
7. 视频 URL、视频 fileId、播放凭证都视为付费字段。
8. 所有扣减行为必须有权益流水记录。
9. 所有完整内容访问应具备幂等标识，避免重复扣减。
10. 文案中应统一使用“完整学习次数”，避免使用“查词次数”造成误解。
11. 收藏、最近学习只是入口，不代表用户永久拥有该单词完整内容。
12. 后续若增加“已学过免扣”“复习模式”“永久解锁”，必须先更新本文档，再进行开发。

## I. 第一阶段推荐开发顺序

1. 明确并实现 `basicWord` / `fullWord` 返回结构。
2. 修正搜索、首页、基础详情接口，确保只返回免费字段。
3. 建立完整内容访问接口，统一处理登录、会员、次数扣减。
4. 加入幂等访问标识，防止网络重试重复扣减。
5. 调整详情页为基础内容 + 完整学习区 + 锁定态结构。
6. 将视频字段限制在完整权限通过后返回。
7. 优化我的页面，展示剩余完整学习次数、会员状态和到期时间。
8. 补齐后台人工添加买书会员流程。
9. 分享奖励、兑换码、订单自动化进入后续阶段。
