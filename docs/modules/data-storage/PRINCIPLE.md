# 数据存储模块原则

## 模块目标

数据存储模块负责记录当前项目中不同数据的真实存储位置、读写边界和迁移约束。

当前项目不是单一数据库架构，而是由服务端 JSON、MySQL 用户表、小程序本地 storage、后台 localStorage、内容种子 JSON 和开发预览桥共同组成。

## 业务规则

- 生产数据库结构变更必须先有 ADR、迁移计划、回滚计划和备份确认。
- 内容 `id` 必须稳定，不能随意变更。
- 用户业务数据应引用 `users.id`，不直接引用 `openid` 或手机号。
- 小程序本地学习数据目前只代表当前设备，不代表云端账号数据。
- 后台本地草稿不等于服务器已发布内容。
- generated build output 和 HBuilderX/微信开发者工具产物不是数据源。
- 开发预览桥写出的本地媒体和 `dev-preview-data.js` 只用于调试。

## 当前设计原则

- 词条内容通过 `word-repository.js` 和 `word-store.mjs` 隔离页面和存储实现。
- 用户身份通过 `user-store.mjs` 隔离 MySQL 表访问。
- 本地学习状态通过 `user-store.js` 限定在小程序 storage。
- 后台草稿和 session 通过后台 localStorage 管理。
- 内容种子和校验脚本作为导入前安全层，不直接代表生产数据库。

## 为什么采用当前方案

MVP 阶段同时需要可运行小程序、可编辑后台和最小服务端 API。直接迁移到完整云数据库、媒体资产库和权益库会扩大范围，因此当前用多层轻量存储先建立边界：

- 公开内容先由服务端 JSON 承接。
- 用户身份先由 MySQL 承接。
- 学习行为暂留本地。
- 后台草稿暂留浏览器。
- 后续迁移时保留 repository/store 边界。

## 与其他模块关系

- 单词内容模块：读取服务端 JSON、内容种子和小程序 fallback。
- 用户认证模块：读取和写入 MySQL 用户表、WeChat 绑定表和小程序 auth storage。
- 视频/VOD 模块：存储媒体元数据和本地预览桥素材路径。
- 管理后台模块：通过 localStorage 保存草稿/导入队列，通过 admin API 写服务端内容。
