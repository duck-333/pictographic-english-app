# 管理后台模块原则

## 模块目标

管理后台模块负责让管理员维护词条内容、拆解、音频、视频片段、插图、导入队列、发布状态和首页推荐。

它必须是独立后台项目或独立 Web 后台入口，不能作为普通小程序页面或隐藏入口暴露给用户。

## 业务规则

- 管理后台必须通过管理员账号密码登录。
- 管理员凭据由服务端环境变量 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 配置。
- 后台 API 使用 Bearer session token。
- 后台可读写 `draft`、`published`、`unpublished`、`archived` 等状态。
- 用户小程序只能读取 `published` 内容。
- 后台本地草稿、未上传队列和浏览器预览状态不能等同于服务器已发布内容。
- 首页推荐只能保存已发布词条。

## 当前设计原则

- 后台项目位于 `admin-portal/pictographic-admin`，独立于 `miniapp-uni/word-app1`。
- 后台主页面当前是单文件内容工作台，先满足 MVP 内容维护闭环。
- 服务端负责认证和内容校验，后台前端负责编辑体验和提交 payload。
- 管理后台不引入新的权限系统或 UI 框架。
- Dashboard 中部分用户/行为统计 API 仍是占位说明，不视为已实现能力。

## 为什么采用当前方案

当前优先级是跑通“内容录入 -> 发布到服务端 -> 小程序读取 published 内容”。单独后台项目能避免把管理入口暴露到用户小程序，同时复用已有 uni-app/HBuilderX 工作流。

把完整角色系统、审计、内容历史、媒体资产系统延后，可以降低 MVP 阶段的实现风险；但当前单文件后台需要在未来明确边界后再拆分。

## 与其他模块关系

- 单词内容模块：后台是词条发布和首页推荐的主要写入入口。
- 视频/VOD 模块：后台维护视频片段、发音音频和本地预览素材。
- 用户认证模块：后台管理员登录使用 `server/auth.mjs`，但不等同于普通用户登录。
- 数据存储模块：后台本地状态存在浏览器 localStorage，服务端发布内容存在 `server/local-data/words.json`。
