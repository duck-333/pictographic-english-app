# Phase 2.3 用户权益系统业务规则开发计划

日期：2026-07-21

状态：Planning

## 1. 目标

本计划记录 Phase 2.3 用户权益系统的业务规则落地顺序。

当前只做文档设计，不修改代码，不创建 migration，不修改 API，不修改小程序。

业务目标：

- 普通用户通过注册赠送、分享奖励、管理员赠送等方式获得完整内容访问额度。
- 月会员有效期内无限查看完整内容。
- 完整内容访问基于 Learning Object Access Model。
- 额度不足时提供明确转化路径。
- 淘宝购书赠会员可以通过后台人工赠送完成。
- 后台可以查询用户权益、查看流水、赠送会员和赠送额度。

## 2. 权益类型规划

### 注册赠送额度

默认规则：

- 新用户注册后赠送 30 次完整内容访问额度。
- 有效期可配置。
- 当前默认有效期暂定一年。
- 只发放一次。
- 不永久解锁内容。

后续开发需要确认：

- 注册赠送触发时机：创建用户时，还是首次登录后初始化权益。
- 默认有效期配置来源。
- 已注册老用户是否补发。
- 补发是否需要后台批处理和流水记录。

### 月会员

默认规则：

- 月会员有效期内无限查看完整内容。
- 不消耗普通额度。
- 不产生永久解锁。
- 会员到期后恢复普通用户规则。

后续开发需要确认：

- 月会员开始时间和到期时间计算方式。
- 续费是否顺延当前会员到期时间。
- 会员赠送和会员购买是否使用同一权益模型。
- 会员过期任务是否需要后台定时校准。

### 运营赠送权益

包含：

- 淘宝购书赠会员。
- 分享奖励额度。
- 管理员手动赠送额度。

后续开发需要确认：

- 淘宝购书赠送的是月会员还是固定天数会员。
- 分享奖励每次奖励多少额度。
- 分享奖励是否有每日上限、总上限和防刷规则。
- 管理员赠送额度默认有效期。
- 管理员赠送会员是否允许选择开始时间和结束时间。

## 3. 完整内容访问规则

采用 Learning Object Access Model。

规则：

- 用户主动搜索并进入一个学习对象，触发一次权益判断。
- 当前 root Learning Object 内部 `decompose` 拆解内容不重复扣减。
- `related` / `recommend` 跳转到新的 Learning Object，需要重新判断权益。
- 不根据页面层级、路由或 `word_id` 写死规则。

建议访问上下文：

```text
root_learning_object_id
current_learning_object_id
relation_type
access_reason
```

示例：

```text
搜索 apple -> root=apple, current=apple -> 权益判断
apple 内展开 pl -> root=apple, current=pl, relation=decompose -> 不重复扣减
搜索 pl -> root=pl, current=pl -> 权益判断
apple 关联 fruit -> root=fruit, current=fruit -> 重新判断
```

后续开发需要确认：

- 哪些内容可以独立成为 Learning Object。
- 哪些关系属于 `decompose`。
- 哪些关系属于 `related` / `recommend`。
- 直接搜索拆解节点时，是否总是视为独立 root Learning Object。

## 4. 额度扣减规则

普通用户：

- 查看完整内容消耗额度。
- 消耗单位是 root Learning Object Access。
- 额度不足时不能访问完整内容。

会员用户：

- 会员有效期内不消耗普通额度。
- 会员有效期内不产生永久解锁。
- 会员过期后重新按照普通权益规则判断。

服务端规则：

- 消耗必须由服务端完成。
- 服务端通过 token 识别用户。
- 服务端写权益流水并更新快照。
- 服务端返回可访问状态、剩余额度或权益不足状态。

小程序规则：

- 不本地判断剩余额度。
- 不本地扣减额度。
- 不自行判断会员有效性。
- 不传 `user_id`。
- 只展示服务端返回的状态。

## 5. 额度不足流程

用户额度不足且无有效会员时，进入内容锁定流程。

建议页面状态：

```text
完整内容已锁定
  -> 开通会员入口
  -> 获取免费额度入口
```

开通会员入口：

- 说明月会员权益。
- 引导购买或兑换。
- 当前阶段可以先设计入口，不接支付。

获取免费额度入口：

- 分享奖励。
- 淘宝购书赠会员说明。
- 联系客服。
- 后续活动入口。

后续开发需要确认：

- 锁定页显示哪些内容摘要。
- 是否允许试听/试看片段。
- 是否展示剩余额度为 0。
- 未登录用户是否先引导登录。
- 权益不足 API 返回状态如何映射到前端 UI。

## 6. 淘宝购书赠会员流程

业务流程：

```text
淘宝购买
  -> 用户联系客服
  -> 提供订单截图 + 手机号
  -> 后台输入手机号
  -> 定位用户账号
  -> 赠送会员
  -> 写权益流水
  -> 记录操作备注
```

后台输入信息：

- 手机号。
- 淘宝订单号或订单摘要。
- 会员赠送类型。
- 赠送时长。
- 操作备注。

后台输出结果：

- 找到的用户账号。
- 赠送后的会员状态。
- 会员到期时间。
- 权益流水记录。

异常情况：

- 手机号未绑定账号：提示用户先登录绑定手机号，或进入人工待处理。
- 手机号匹配多个异常账号：停止自动赠送，转人工核查。
- 订单截图不清晰：不发放，备注原因。
- 重复订单：依赖订单摘要或后台备注防止重复赠送。

## 7. 后台权益管理需求

### 查询用户权益

后台应支持按手机号或用户 id 查询：

- 当前普通额度余额。
- 普通额度有效期概况。
- 当前会员状态。
- 会员类型。
- 会员到期时间。

### 查看权益流水

后台应支持查看：

- 注册赠送。
- 完整内容访问消耗。
- 分享奖励。
- 管理员赠送额度。
- 淘宝购书赠会员。
- 会员开通。
- 会员到期。
- 退款恢复。

### 赠送会员

后台赠送会员需要填写：

- 用户账号。
- 会员类型。
- 赠送时长或到期时间。
- 操作备注。

必须写入权益流水。

### 赠送额度

后台赠送额度需要填写：

- 用户账号。
- 赠送次数。
- 有效期。
- 操作备注。

必须写入权益流水。

### 操作备注

所有后台人工操作都必须有备注。

备注应说明：

- 为什么赠送。
- 来源是什么。
- 是否关联淘宝订单、客服记录或活动。

## 8. 开发阶段建议

### 阶段 A：业务规则确认

确认：

- 注册赠送是否固定 30 次。
- 注册赠送默认有效期。
- 月会员价格和时长。
- 淘宝购书赠送会员时长。
- 分享奖励额度和限制。
- 管理员赠送默认有效期。

交付：

- 业务规则冻结。
- 后台操作字段确认。
- 锁定页文案方向确认。

### 阶段 B：数据库与服务端模型

基于 ADR-0020 设计：

- `entitlement_transactions`
- `user_entitlements`

注意：

- 本计划不创建 migration。
- 后续开发阶段再创建 SQL。

### 阶段 C：权益检查与扣减服务

实现方向：

- 服务端根据 token 识别用户。
- 服务端读取权益快照。
- 服务端判断会员状态。
- 服务端按 Learning Object Access Context 判断是否扣减。
- 服务端写流水并更新快照。

### 阶段 D：额度不足前端流程

实现方向：

- 小程序展示内容锁定页。
- 提供开通会员入口。
- 提供获取免费额度入口。
- 小程序只展示服务端返回状态，不本地判断权益。

### 阶段 E：后台权益管理

实现方向：

- 查询用户权益。
- 查看权益流水。
- 赠送会员。
- 赠送额度。
- 填写操作备注。

### 阶段 F：运营赠送闭环

实现方向：

- 淘宝购书赠会员人工流程。
- 分享奖励额度。
- 管理员赠送额度。

## 9. 明确禁止事项

本阶段不要：

- 修改 `server/**`。
- 修改 `database/**`。
- 创建 migration。
- 修改小程序页面。
- 修改 API。
- 修改 `package.json`。
- 实现支付。
- 实现会员购买。
- 实现后台页面。

业务规则层也不采用：

- 永久解锁。
- `user_unlocked_words`。
- `word_unlock_records`。
- 页面路径扣减。
- `word_id` 硬编码扣减。
- 本地 `searchCount` 判断额度。
- 小程序本地判断会员。

## 10. 验收方向

未来开发完成后，业务验收应覆盖：

- 新用户获得 30 次注册赠送额度。
- 普通用户主动进入 root Learning Object 消耗 1 次额度。
- root 内部 `decompose` 不重复扣减。
- `related` / `recommend` 新对象重新判断权益。
- 月会员访问完整内容不扣普通额度。
- 月会员过期后恢复普通规则。
- 额度不足展示锁定页、会员入口和获取免费额度入口。
- 淘宝购书赠会员可以通过后台人工赠送完成。
- 后台赠送和调整都有流水和备注。

## 11. 当前不做

本计划只做业务规则设计，不进入开发。
