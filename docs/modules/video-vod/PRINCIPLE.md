# 视频/VOD 模块原则

## 模块目标

视频/VOD 模块负责让词条关联讲解视频片段、完整视频入口、发音音频和本地预览素材，使用户能在单词详情页看到对应讲解内容。

当前实现是内容字段和前端播放能力，不是完整 VOD 平台，也不是付费/会员权限系统。

## 业务规则

- 数据库或内容记录只保存媒体元数据：URL、开始秒、结束秒、标题、焦点、关联部件、资产 ID 等。
- 视频文件本体不进入正式内容 JSON 正文。
- 生产可播放媒体必须使用合法 HTTPS/cloud URL，并配置到微信合法域名。
- localhost、127.0.0.1、blob、data、mock-cloud、example.com 只允许作为开发或演练路径，不能进入生产公开内容。
- `startSec` 和 `endSec` 必须是非负数，且 `endSec > startSec`。
- 客户端视频片段裁剪只是体验能力，不是会员或付费安全边界。
- 当前完整视频按钮只是已有 URL 下的播放入口，未接入权益判断。

## 当前设计原则

- 媒体字段跟随词条记录，由 `content-schema.js` 标准化。
- 小程序详情页通过统一媒体 guard 判断是否可播放。
- 后台页面支持选择本地媒体、模拟上传、编辑片段列表和同步到本地预览桥。
- 本地预览桥只服务电脑端微信开发者工具调试，不能作为线上媒体服务。
- 生产检查脚本负责阻断典型本地/mock/example 媒体值。

## 为什么采用当前方案

MVP 阶段优先解决“一个词条能对应一个或多个讲解片段，并能在小程序详情页播放”的路径。直接接入完整 VOD SDK、转码、签名播放和会员鉴权会显著扩大范围，因此当前采用字段化媒体元数据和最小前端播放器。

这个方案让内容编辑和用户端展示先跑通，同时保留未来接入云存储、点播、签名 URL 和会员权限的空间。

## 与其他模块关系

- 单词内容模块：视频片段、发音音频、插图都作为词条字段返回。
- 管理后台模块：后台维护视频片段和音频字段。
- 数据存储模块：服务端 JSON 和内容种子保存媒体元数据；预览桥写入本地 dev-preview 文件和素材目录。
- 用户认证模块：当前无依赖；未来会员/VOD 权限必须接入服务端认证和权限判断。
