# ADR-0021: Phase 2.3 用户权益系统业务规则设计

日期：2026-07-21

状态：Proposed

## 背景

Phase 2.3 已完成用户权益系统架构和数据库模型规划：

- ADR-0019 定义用户权益系统架构和 Learning Object Access Model。
- ADR-0020 定义 `entitlement_transactions` 与 `user_entitlements` 的数据库模型方向。
- `phase-2.3-user-entitlement-plan.md` 定义权益系统阶段规划。

本 ADR 进一步冻结商业规则层设计，用于后续数据库、服务端、小程序和后台开发前对齐产品边界。

本 ADR 不实现功能，不修改代码，不创建 SQL，不新增 migration。

## 业务目标

权益系统用于回答：

```text
当前用户是否可以查看某个 Learning Object 的完整内容？
如果不能，应展示什么转化入口？
如果可以，是否需要消耗普通额度？
后台如何查询、赠送和审计用户权益？
```

完整内容包括但不限于：

- 象形拆解。
- 视频讲解。
- 示意图。
- 专属教学内容。

## 权益类型

### 1. 注册赠送额度

规则：

- 新用户注册后默认获得 30 次完整内容访问额度。
- 有效期必须设计为可配置，当前产品默认值暂定一年。
- 注册赠送只发放一次。
- 注册赠送不代表永久解锁任何内容。
- 注册赠送消耗后应写入权益流水。

原因：

- 默认 30 次可以降低首次使用门槛。
- 有效期可配置可以适配后续运营调整。
- 不做永久解锁可以避免会员结束后仍无限访问历史内容。

### 2. 月会员

规则：

- 月会员有效期内可以无限查看完整内容。
- 月会员有效期内不消耗普通额度。
- 月会员有效期内不产生永久解锁。
- 月会员到期后恢复普通用户权益规则。
- 如果用户还有未过期普通额度，到期后可以继续按额度访问。
- 如果用户没有有效额度，也没有有效会员，则完整内容不可访问。

说明：

- 会员是一种当前访问资格，不是历史访问资产。
- 会员过期后不能继续无限访问会员期间看过的全部内容。

### 3. 运营赠送权益

运营赠送权益包括：

- 淘宝购书赠会员。
- 分享奖励额度。
- 管理员手动赠送额度。

规则：

- 所有赠送都必须归属到登录用户账号。
- 所有赠送都必须写入权益流水。
- 所有赠送都必须记录来源、操作人或业务来源、备注和时间。
- 额度型赠送必须支持有效期。
- 会员型赠送必须记录会员类型、开始时间和到期时间。

## 完整内容访问规则

完整内容访问采用 Learning Object Access Model。

### 主动进入学习对象

用户主动搜索并进入一个 Learning Object，触发一次权益判断。

示例：

```text
搜索 apple -> 进入 apple -> 权益判断
搜索 pl    -> 进入 pl    -> 权益判断
搜索 p     -> 进入 p     -> 权益判断
```

如果用户是普通用户且有额度，则消耗一次额度。

如果用户是月会员且会员有效，则允许访问，不消耗普通额度。

### 内部 `decompose` 展开

当前 root Learning Object 内部的 `decompose` 拆解内容不重复扣减。

示例：

```text
apple
  ├── ap
  ├── pl
  └── e
```

用户进入 `apple` 时已经完成一次权益判断。随后查看 `ap`、`pl`、`e` 属于 `apple` 的内部学习过程，不额外消耗额度。

### `related` / `recommend` 跳转

`related` / `recommend` 指向新的 Learning Object 时，需要重新判断权益。

示例：

```text
apple 页面
  -> related fruit
  -> 用户点击 fruit
  -> fruit 成为新的 root Learning Object
  -> 重新判断权益
```

### 禁止硬编码判断

权益判断不根据以下内容实现：

- 页面层级。
- 页面路由。
- `word_id` 硬编码。
- `apple` / `pl` / `p` 这类特殊规则。
- 是否曾经访问过某个词条。

权益判断必须基于：

```text
Learning Object + Access Context
```

## 额度扣减规则

### 普通用户

普通用户主动访问 root Learning Object 的完整内容时：

- 有有效额度：服务端消耗 1 次额度，允许访问完整内容。
- 无有效额度：服务端拒绝完整内容访问，返回权益不足状态。

### 会员用户

月会员有效期内：

- 完整内容访问不消耗普通额度。
- 不产生永久解锁。
- 可记录访问流水或学习事件，但不能把访问过的 Learning Object 变成永久可访问资产。

### 服务端负责扣减

额度扣减必须由服务端完成。

小程序不能：

- 本地判断剩余额度。
- 本地扣减额度。
- 自行判断会员有效性。
- 传入 `user_id` 让服务端使用。
- 基于本地 `searchCount` 或页面路径决定访问资格。

服务端必须：

- 通过 `Authorization: Bearer <token>` 鉴权。
- 通过 `requireUserAuth()` 得到 `authResult.userId`。
- 基于用户当前权益和访问上下文判断。
- 在需要扣减时写入权益流水并更新权益快照。

### 不设计永久解锁

明确不设计：

- `user_unlocked_words`
- `word_unlock_records`
- 永久解锁 Learning Object 的访问表

原因：

- 当前商业模式是当前权益访问，不是词条买断。
- 会员结束后不能继续无限访问会员期间看过的全部内容。
- 永久解锁会增加退款、会员、赠送额度和活动奖励之间的冲突。

## 额度不足流程

当普通用户额度不足且没有有效会员时：

1. 服务端返回权益不足状态。
2. 小程序展示内容锁定页或锁定态。
3. 页面提供开通会员入口。
4. 页面提供获取免费额度入口。

内容锁定页应表达：

- 当前完整内容需要权益才能查看。
- 用户可以开通月会员。
- 用户可以通过运营活动获得免费额度。
- 已登录用户可以查看当前权益状态。

获取免费额度入口可以包括：

- 分享奖励。
- 购书赠会员说明。
- 联系客服。
- 后续活动入口。

注意：

- 锁定页只展示入口，不做本地权益判断。
- 具体可访问状态必须以后端返回为准。

## 淘宝购书赠会员流程

业务流程：

```text
淘宝购买
  -> 用户联系客服
  -> 用户提供订单截图 + 手机号
  -> 后台输入手机号
  -> 查询或定位用户账号
  -> 赠送月会员
  -> 写入权益流水
  -> 记录后台操作备注
```

后台操作需要记录：

- 操作人。
- 操作时间。
- 用户手机号或匹配到的用户账号。
- 赠送会员类型。
- 会员开始时间。
- 会员到期时间。
- 淘宝订单信息摘要。
- 备注。

设计原则：

- 不把淘宝订单截图原图直接作为权益核心数据。
- 后台赠送必须写权益流水。
- 手机号只用于定位用户，权益最终必须归属到 `users.id`。
- 如果手机号未绑定账号，需要有人工处理状态，不能直接创建不明确的权益归属。

## 后台权益管理原则

后台未来需要支持以下能力：

### 查询用户权益

后台可以按用户 id、手机号或其他已确认账号标识查询：

- 当前普通额度余额。
- 普通额度有效期概况。
- 当前会员状态。
- 会员类型。
- 会员到期时间。

### 查看权益流水

后台可以查看：

- 注册赠送。
- 完整内容访问消耗。
- 分享奖励。
- 管理员赠送。
- 淘宝购书赠会员。
- 退款恢复。
- 会员开通和到期。

流水必须能解释当前权益状态。

### 赠送会员

后台赠送会员时必须填写：

- 用户账号。
- 会员类型，例如月会员。
- 生效时间。
- 到期时间或赠送时长。
- 操作备注。

赠送结果必须写入权益流水，并更新用户当前权益快照。

### 赠送额度

后台赠送额度时必须填写：

- 用户账号。
- 赠送次数。
- 有效期。
- 操作备注。

赠送结果必须写入权益流水，并更新用户当前权益快照。

### 操作备注

所有人工操作必须有备注。

备注用于：

- 客服排查。
- 财务或运营复盘。
- 用户投诉处理。
- 异常操作审计。

## 决策

Phase 2.3 用户权益系统业务规则确定如下：

- 默认注册赠送 30 次完整内容访问额度。
- 注册赠送额度有效期可配置，当前默认一年。
- 月会员有效期内无限查看完整内容，不扣普通额度。
- 月会员不产生永久解锁，到期后恢复普通权益规则。
- 运营赠送包括淘宝购书赠会员、分享奖励额度、管理员手动赠送。
- 完整内容访问采用 Learning Object Access Model。
- 额度扣减必须由服务端完成。
- 小程序不能本地判断余额、会员状态或扣减结果。
- 额度不足时展示内容锁定页，并提供会员入口和获取免费额度入口。
- 后台权益管理必须支持查询、流水、赠送会员、赠送额度和操作备注。
