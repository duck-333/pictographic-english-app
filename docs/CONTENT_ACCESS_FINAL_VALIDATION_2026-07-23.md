# CONTENT_ACCESS 最终验证记录

日期：
2026-07-23

## 1. 验证目的

记录内容访问权益系统（`CONTENT_ACCESS`）上线后的最终回归验证结果。

确认以下规则：

- 用户主动打开完整单词详情时消耗 1 次权益。
- 列表展示、搜索、推荐等预加载不会消耗权益。
- 收藏、最近学习等入口重新进入详情时，仍按照主动访问处理，需要重新消耗权益。
- 没有完整内容的词条不会消耗权益。

## 2. 验证环境

测试方式：

微信开发者工具模拟器 + 独立测试设备

数据库验证：

MySQL

数据表：

`entitlement_transactions`

验证字段：

- `transaction_type`
- `amount`
- `user_id`
- `source`
- `created_at`

## 3. 测试结果

### 测试 1：主动进入单词详情

操作：

用户进入 `study` 页面。

点击单词进入详情页。

结果：

新增一条：

`CONTENT_ACCESS`

扣减：

`amount = -1`

数据库验证：

通过。

结论：

主动详情访问正确消费权益。

---

### 测试 2：首页/列表刷新

操作：

返回首页。

刷新页面。

加载推荐、搜索、收藏等列表。

结果：

没有新增 `CONTENT_ACCESS`。

结论：

列表展示不会误扣权益。

---

### 测试 3：收藏进入详情

操作：

搜索单词。

收藏。

从收藏列表再次进入单词详情。

结果：

新增一条：

`CONTENT_ACCESS`

扣减：

`amount = -1`

结论：

收藏只是入口，不代表永久拥有完整内容权限。

符合当前商业规则。

---

## 4. 已验证规则总结

会消费：

- 单词详情页主动访问
- 收藏进入详情
- 最近学习进入详情
- 有完整内容的词根/关联词详情

不会消费：

- 搜索列表展示
- 首页推荐展示
- 收藏列表加载
- 最近学习列表加载
- 无完整内容词条

## 5. 当前技术实现确认

客户端：

只有主动详情访问请求传递：

```js
accessContent: true
```

并携带：

`clientRequestId`

服务端：

收到完整内容访问请求后：

```text
Authorization 校验用户身份
↓
consumeQuota()
↓
写入 entitlement_transactions
```

## 6. 已解决问题

历史问题：

部分列表预加载请求自动携带登录态，导致进入详情消费逻辑。

修复：

限制 `Authorization` 只用于主动内容访问请求。

结果：

避免列表加载导致重复扣减。
